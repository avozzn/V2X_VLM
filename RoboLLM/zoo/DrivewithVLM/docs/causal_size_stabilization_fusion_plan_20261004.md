# 双端因果尺寸稳定、关联与对象融合实施计划

日期：2026-10-04。状态：尺寸稳定、补偿、软关联、高可信判断、尺寸选择/融合已实现，并完成 train929/val157、冻结后 test480 的 A0–A4 对照；28项相关测试通过。最新用户范围是通过cor评估几何算法，不包含T1/S1输入导出或VLM训练。原生标注未修改。

实施结果见[完整验证报告](../evaluation_results/stable_fusion_v1_20261004/report.md)；**仅时间补偿与尺寸波动降低获得支持，软关联/高可信及尺寸平均未通过本轮验收，冻结保留A1。**

## 1. 目标与已有基础

目标链路如下；本轮实现至尺寸选择／融合及离线评估，最后的ROI预算、T1/S1共同输入导出留待后续：

```text
每端原生对象＋本端因果历史
        ↓
本端尺寸稳定＋路端运动补偿＋当前ego坐标对齐
        ↓
中心距离＋朝向＋软BEV IoU候选关联
        ↓
高可信配对去重；选择／融合尺寸；不确定对象保留
        ↓
固定ROI与预算 → 对象文本 / soft tokens → VLM
```

已有：双端原生JSON、完整原生PKL、连续v3规划split929/157/480；tools/association已实现参考身份审计、路端因果恒速补偿和A/B/C扫描。补偿后val固定诊断设置的参考召回88.46%，不是已验收的生产去重规则。

目标是提高关联与输入稳定性，不宣称恢复精密测量的物理真值。cooperative身份与框只能进入离线评估；原生GT、修订估计、检测预测必须保留来源区别。首版不建立稠密BEV、不改检测器、不将路端信息送到VLM后的planner。

## 2. 数据处理与接口

### 2.1 两端各自建立因果历史

扩展NativeDataset，使两端都有按sequence/time排序的原生frame索引。历史键为side/sequence/track_id；首版属于GT轨迹Oracle，后续Detector必须换成本端预测tracker ID，不能继承GT身份。

每个当前对象只取本端时刻之前1秒内的历史，最多4次有效观测，加当前帧共最多5次。历史不能晚于路端消息时刻，即便它早于ego时刻；跨sequence重置。当前帧无对象时不凭历史补出对象。缺失/重复ID、统一类别变化、时间异常时不更新对应尺寸记忆。两端原始类别仍保留，Bus/Car差异不直接删除对象。

### 2.2 本端尺寸稳定与运动补偿

只对vehicle类启用尺寸稳定；pedestrian/cyclist首版保持原始尺寸，避免把行人姿态、自行车与骑行者框变化误当噪声。

有效窗口不少于3次观测时，分别取l/w/h中位数作为stable_lwh；否则回退当前raw_lwh并标size_stable_valid=false。记录样本数、每维MAD和相对MAD；MAD是历史离散度，不是校准后的测量方差。全部按米制物体自身轴尺寸处理，不按图像距离缩放。

运动补偿沿用现有算法：最近过去同track原生位置先到世界坐标，估计平面绝对速度，推进到ego时刻再变到当前ego LiDAR。车端当前框不外推，车端历史只用于尺寸稳定。缺历史则仅空间对齐，motion_valid=false；不引入下一观测GT速度或历史插值补框。

### 2.3 新对象合同

宽候选缓存新增raw_lwh、stable_lwh、size_stable_valid、size_history_count、size_mad_lwh、原始/稳定/补偿框、history_frames/timestamps。保留source frame/sequence、年龄、速度有效性、标定和输入hash。

后续VLM最终输入每个对象至少有geometry13、velocity_valid、source_bits=[ego_seen,rsu_seen]、size_policy、size_conflict；内部另保留贡献对象索引和原生身份用于追溯。ID/token不进入文本或embedding。双端来源用两位编码，避免融合后伪装成仅车端对象。内部历史统计首轮不全部输入VLM。

新接口和归一化配置版本化；不复用旧planner缓存或旧对象encoder checkpoint。未知速度数值可存0，但有效性必须为false。

## 3. 关联、可信度与尺寸融合

### 3.1 候选关联

统一三类；不同类禁止配对。默认候选中心距离门限vehicle2m、pedestrian/cyclist1m，与现有诊断一致，不先扩大范围。

vehicle/cyclist朝向差按物体轴计算：delta_axis=acos(abs(cos(yaw_ego-yaw_rsu)))，范围0～pi/2，避免前后180度翻转破坏关联。pedestrian不使用朝向。朝向用于关联兼容性；不据此改写真实运动朝向。

首版代价：vehicle/cyclist为0.6*(distance/gate)+0.3*(1-BEV_IoU)+0.1*(delta_axis/(pi/2))；pedestrian为0.7*(distance/gate)+0.3*(1-BEV_IoU)。尺寸通过稳定框的IoU进入，不额外重复施加强尺寸惩罚。IoU是软项，无硬IoU门限，不用cooperative ID预先统一尺寸。

增加带未匹配项的Hungarian：每个ego对象有独立dummy，默认代价0.7；非法边无限大。不要沿用旧“先最大化匹配数量”的大惩罚，否则可能强行接受弱候选。

### 3.2 高可信判断与保守去重

Hungarian配对之后再次验收：该配对在两端候选中均为最低代价；两端相对次佳候选的代价差均至少0.1；没有次佳候选时按差距无限处理。中心距离还需≤候选门限的一半；vehicle/cyclist轴向差≤30度；路端age≤1s，且有正age时motion_valid必须为true。上述是首版工程默认，先报告实际coverage，不宣称参数已经最佳。

只有通过的配对去重。低可信配对保留两端独立对象，记录歧义；未匹配路端对象保留补偿框。尺寸冲突不直接否定身份，但阻止激进尺寸平均。配对判断只用当时可得几何与历史；参考ID不可进入判断。

### 3.3 高可信配对后的几何政策

先固定融合对象的中心、yaw和主速度为当前ego值，避免把旧路端状态平均进当前状态；source_bits设为[1,1]。路端速度不用于填补未知ego速度，首轮减少机制叠加。

提供两个尺寸政策，使用完全相同的高可信配对：

- 默认select_ego：选ego本端稳定尺寸；不足历史时选ego当前尺寸。路端独有对象选路端稳定尺寸。
- 对照blend_stable：仅vehicle、两端稳定尺寸均有效、各维相对MAD≤0.1且两端各维相对差≤0.2时，采用两端stable_lwh的等权算术平均；否则回退select_ego并标冲突或证据不足。不把稳定度转换为未经校准的逆方差权重。

保留两端原始尺寸和政策记录；不修改原生JSON，不把平均后的尺寸命名为GT。

关联、补偿和去重在宽候选上完成。本轮未做ROI/top-K；后续输入导出再固定ego当前原点50m ROI。ego贡献对象最多32、额外RSU对象最多16；融合对象计入ego预算，按统一坐标平面距离排序，同距按固定数值字段打破平局。低可信双端对象会占各自预算，报告预算截断，不能把截断称去重收益。

## 4. 原计划实施顺序与本轮完成范围

本轮实际按A0无补偿 → A1补偿 → A2尺寸稳定 → A3软关联＋高可信 → A4条件尺寸平均进行单因素对照，见第6节。下表P0独立尺寸归因与P4输入导出仍为后续任务；P1–P3的算法与完整离线实验已完成。

| 阶段 | 工作 | 验收 / 交付 |
|---|---|---|
| P0 | 尺寸因素离线诊断 | 已知参考对保持中心/yaw固定，比较原始尺寸、双端平均尺寸、统一ego尺寸的IoU与跨门限数；只用于归因，不接入正式匹配 |
| P1 | 两端历史和尺寸稳定 | 导出历史证据、raw/stable尺寸与MAD；检查异常与因果性 |
| P2 | 软关联和高可信验收 | 相同候选上比较旧补偿A、软关联未稳定尺寸、软关联稳定尺寸；先保留ego尺寸，不同时平均中心 |
| P3 | 尺寸选择/平均对照 | 固定P2配对，比较select_ego与blend_stable的尺寸连续性、冲突率和cooperative一致性代理；默认select_ego，平均版只作对照 |
| P4 | 共享对象输入导出 | 新版本train/val/test929/157/480；同一缓存分别生成T1文本和S1对象输入，之后再实施VLM训练接口 |

P0～P3先完整train/val CPU实验，不训练VLM，不用test挑规则。默认不追加大规模参数扫描；若高可信可判定精确率低于现有诊断99.87%，暂不把新规则作为正式去重默认，保留独立对象并输出失败案例。精确率分母有限，必须同时报告未知匹配和高可信覆盖率，不能把未知当正确。

指标：参考召回、可判定精确率、错误合并、未知配对、密集场景歧义、高可信去重覆盖；原始/稳定/融合尺寸的时序变化、双端尺寸冲突；按类别/年龄/历史有效性分组。cooperative尺寸一致性仅作代理，不能证明实物精度；无可靠可见性证据时RSU-only保留率记未评估。

测试必须覆盖：静止/匀速和ego移动；历史缺失、重复ID、跨scene、类别变化、未来历史诱饵；尺寸单帧异常；180度朝向翻转；密集邻车；零IoU但中心接近；dummy未匹配；高可信与歧义配对；尺寸冲突回退；同对象不重复计预算；空消息/零对象；文本与soft-token字段一致、padding/valid mask正确。

新产物使用不存在的新目录，split转换后原子写入，全部核查通过再发布manifest；旧数据和现有训练保持原样。代码扩展tools/association；共享对象导出另设独立入口，不把新JSON直接交给旧连续planner。

## 5. 参考与结论边界

本地参考：tools/association的原生读取/历史补偿/几何IoU；tools/continuous/prepare.py的ROI和13D顺序；ego_perception.py的原生来源/hash与文本隔离。主输入方案仍以roadside_agent_token_fusion_plan.md为准。

Where2comm补标补的是视野外对象，并非明确的“统一双端长度再IoU”算法；其DAIR-V2X-C补标不可直接套到SPD：[作者补标说明](https://siheng-chen.github.io/dataset/dair-v2x-c-complemented/)。本计划的历史中位数、软关联、高可信验收和尺寸政策是本项目设计，不归为该论文原始实现。

GT阶段可以验证输入稳定性与规划价值；最终Detector需因果预测轨迹与可校准质量信息。若要证明真实物理尺寸更准确，需要独立的人工复核/测量参考，不以“强行统一后IoU升高”作为证据。
