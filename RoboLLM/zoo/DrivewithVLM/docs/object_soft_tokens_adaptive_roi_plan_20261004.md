# 双端对象 soft tokens 与自适应选取范围

日期：2026-10-04。状态：用户确认双端共享对象表示方向；本文为设计与实验计划，尚未实现或训练。

## 1. 下一版输入合同

保留 I1 原始车端图像 tokens。独立 vehicle-side GT 和 infrastructure-side GT 分别导出，统一至当前 ego LiDAR 坐标，再用共享 ObjectEncoder + 来源 embedding 编码。自车状态/因果历史使用独立 StateEncoder。所有对象、状态都进入 VLM；planner 只读取规划 token hidden，不接收 RSU 旁路。

```text
独立车端 GT ──────────────┐
                         ├─ 坐标/时间审计 ─ 对象选择 ─ 共享 ObjectEncoder + source ─┐
独立路端 GT ──────────────┘                                                     │
车端图像 ─ 现有视觉编码器/投影 ────────────────────────────────────────────────┤
自车状态/因果历史 ─ StateEncoder ─────────────────────────────────────────────┤
固定文本提示 ─────────────────────────────────────────────────────────────────┤
                                                                               ↓
                                                      VLM → 规划 hidden → 轨迹 head
```

对象核心沿用 13D，另传 padding、分量有效性、source、age 等字段；缺失速度置零必须带 velocity_valid=false，避免学成静止。来源编码表示 ego/RSU，不以 Oracle/Detector 身份给模型提示。共享物理尺度归一化，不随选择半径变化，否则同一位置在不同帧编码不同。首版独立保留双端观测，同一物体两份 token 标明来源；关联/合并单独消融，不能把两个来源的 GT 合并当成两端各自观测。

对象文本改 soft tokens 时，主对照删除重复对象文本，固定驾驶提示不删。数值 state 替换其文本另作对照，避免同时变化无法归因。当前实现只支持 RSU soft tokens，ego 对象/state 仍为文本；共享 encoder/StateEncoder 尚未接入。

## 2. 路侧看不见自车时如何选取

选择中心为当前 ego LiDAR 原点，而非路侧相机或图像中心。标定/定位有效时，用 T_ego_current←RSU_message 变换路侧对象中心，并计算 hypot(x,y)。该变换需要明确消息时刻与当前 ego 时刻，不能对跨时刻局部坐标直接相减。图像不含自车不妨碍变换；没有可用相对位姿，则不能可靠计算自车距离，也不能用图像中“猜自车位置”替代标定。

路侧画面没看到自车、收到消息但无相关对象、未收到消息是不同状态。保留元数据并分别统计。RSU-only 按真实独立观测/可靠关联定义，不将范围内对象自动称为遮挡对象。距离过滤不能创造标注范围外的观测。

## 3. 范围与 token 预算分开设计

第一层是宽候选区域，由数据/标定可靠覆盖确定上限，记录截断情况；第二层是规划相关区域；第三层是固定 token 预算 K。可变半径不等于可变 token 数；比较方法时必须控制总预算，避免只是多看对象。

阶段 A：固定范围 + nearest Top-K，建立共享双端 soft-token 基线。先沿用 50m，再在更宽候选缓存中验证若干固定范围，具体值由数据覆盖与训练/validation 选择。

阶段 B：因果速度自适应，初始规则 R(v)=clip(R_min+|v|T_look+margin,R_min,R_max)。T_look 可先与规划时域对应，数值是待验证超参数而非论文结论或安全保证。更合理的版本是前向走廊：前方随车速延伸，后方和横向保留基础覆盖。不能因停车就删掉横向来车、行人。

阶段 C：预算内规划相关性排序。依据当前/历史可得的相对位置、方向、可靠速度、目标类别、潜在冲突、消息年龄、定位不确定性和车路信息互补性排序。近处静止停车可能低于较远横穿目标。用当前状态/可用导航构造粗略可达走廊，而非未来 GT 轨迹；导航缺失或转弯不确定时保留多个方向和较宽横向覆盖。速度未知时不计算虚假的精确 TTC，退回保守几何规则。消息老化增加位置不确定性；年龄惩罚不能直接排除危险但陈旧的唯一 RSU 观测。

预算中保留近场、行人/骑行者和路侧独有观测的候选配额，配额值及是否有效需消融。选择前统计候选数，选择后记录对象 ID/来源/选择原因/年龄，便于失败分析。对象选择仅在 VLM 上游；预测后不得再用 RSU 改轨迹。连续帧可用因果滞回减少边界反复进入/退出。

## 4. 用户所述检测优化方案的适配边界

TF-ETCP：公开检索未找到可核实的同名原始论文或代码，以下仅按用户提供的描述评估，不将细节当作已核实文献。

| 方法 | 可借鉴部分 | 当前不宜直接照搬的部分 |
|---|---|---|
| Match–Refine–Append 时序候选 | 同场景因果历史对象 memory；时间对齐、关联、补充当前未观测目标，携带 age/uncertainty | 按测试帧时序索引查询预存标注/未来框不可接受；静态参数存储不自动消除泄漏。候选来源必须是截至当前可得观测，scene reset、TTL、速度有效性明确 |
| 更细 BEV / 类别峰值保留 | 之后在 D1/D2 detector 上改善小目标输入质量 | 当前 GT 已提供 box，ObjectEncoder 没有 BEV 热力图；升 1024 不直接改变 GT token 质量，算力与 AP/规划收益须单独验证 |
| 类别 Circle NMS | Detector 同源重复框清理时按尺度评估 | 0.70/0.50/0.25m 为去重尺度，不是 ego ROI；不能作为双端关联或 GT 删除规则，避免误删相邻行人/骑行者 |

双端重复首先是跨源关联问题，不能当成普通 NMS。优先利用可靠 ID/类别/时间/位置/尺寸/yaw 一致性；无稳定关联时保留带来源的两份观测。第一版 GT 不做位置 refinement，以免修改准确标注导致新误差；历史补充的收益主要在 Detector 漏检、真实可见性缺失或明确标识的遮挡模拟下验证。模拟遮挡不能冒充真实 occlusion。

## 5. 实验顺序与证据

1. 先实现双端 GT soft tokens，同 head、同输入来源、同 split，比较 ego-only / ego+RSU；确认对象 token 有梯度、来源/空消息/无效速度正确，真实 7B 接口能运行。
2. 固定几何选择下，对象文本与 soft tokens 对照；StateEncoder 单独开关，检查 state-only、无图像、无 RSU 消融，避免状态主导掩盖对象失效。
3. 重导宽候选缓存，固定模型与预算：固定范围 nearest-K、速度范围 nearest-K、固定候选范围相关性 Top-K、可变范围相关性 Top-K，分别独立训练；所有范围选择只用因果输入。固定/动态规则共享最大可用覆盖；范围和排序因素分开比较。
4. 先固定 ego/RSU 各自预算评估规则，再固定总预算研究跨源配额动态分配。先固定 encoder/head 配方；VAE/GRU 升级后另复验，不能与选取策略同时变化。
5. Detector 输入阶段再研究时序 memory、关联和类别去重，按来源分阶段替换 GT；不能把 GT confidence=1 解释成现实置信度。

报告主 L2@1/2/3s 与平均、分开 3s/4.5s FDE、coverage，以及近交叉口/VRU/RSU 无相关对象/消息年龄分组。记录有效 token 数、延迟、候选截断率、source 占比及随车速分布。若无可靠碰撞评测保持 null；若研究通信收益，区分 VLM token/计算节省与实际 RSU 传输字节：车端收到完整消息后筛选不自动节省链路带宽。

未来 GT 仅可用于训练监督或离线选择器漏选诊断，不作为推理选取输入。多个 seed 与 scene 分组评估；validation 选型，test 最终一次报告。当前小数据量下优先规则基线，再考虑可学习打分；硬 Top-K 不天然可微，后续需明确软门控/辅助训练方案和筛选监督，不能声称轨迹 loss 已训练离散选择器。

## 6. 创新定位与原始来源

动态空间选择本身已有相关工作。Where2comm 用空间置信图选择通信区域；Selective Communication 研究端到端驾驶中与导航相关的信息选择。因此暂不声称“可变距离”首次提出。更具体的待验证方向是：在保留原始图像的 VLM 中，以规划相关性、消息年龄/不确定性及双端互补性组织对象 token，在固定 token 预算下提升协同规划。需要同时证明规划改善、关键目标保留及计算代价，而非仅给半径起新名字。
